# Prototype → Production data migration plan (NOT executed)

Flow: **Prototype data (S in localStorage) → Mapping → Migration script → Validation → Production DB.**
Do it only after the corresponding module exists, and only for data the owner wants to keep (the prototype data is demo data).

| Prototype (S) | Target | Notes |
|---|---|---|
| `c[]` | `customers` | `k` → `op_letter`; `ph` → `phone`; `inv` (a number) is NOT migrated as an invoice — needs real invoices (Customer financial module). `c[].p[]` → customer payment documents + `financial_transactions`. |
| `w[]` | `employees` (+ `profiles` for those who log in, + `employee_pay_terms`) | `id` (array index) is dropped; `code` is regenerated by sequence (old EMP codes may differ). `idimg` (data URL) → Storage upload. |
| `pm` | `user_roles` / `user_permissions` | Old 14 coarse keys map to many dotted keys — mapping table needed (owner decision). |
| `ac`, `led` | `financial_accounts` + `financial_transactions` | Ledger rows become opening balances or typed transactions; duplicated rows (document + ledger) must be de-duplicated. |
| `fb` | `inventory_transactions` (fabric items, customer-owned) | Colors become items/variants (decision needed). |
| `m`, `sh` | purchase documents + `inventory_transactions` + `financial_transactions` | Needs item master + suppliers. |
| `o`, `b`, `t`, `l` | production orders, bundles, `production_transactions`, worker ledger | Prototype rework/rejected accounting is WRONG (see audit) — recompute, do not copy `t` blindly. |
| `x`, `cat`, `mc`, `mt`, `lg` | expenses, categories, machines, maintenance, (audit not migrated) | |

Validation checklist per module: row counts, sum of money per account, stock per item/warehouse/owner, customer balances, orphan references = 0, then owner sign-off. Rollback = restore backup taken before the run.
